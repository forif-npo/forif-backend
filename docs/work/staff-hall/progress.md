## 2단계 구현 내용

| 구분        | 파일                                                                                          |
| ----------- | --------------------------------------------------------------------------------------------- |
| migration   | `db/migration/V5__add_staff_recruitment.sql` (3개 테이블 신규, 기존 테이블 변경 없음)          |
| domain      | `domain/staffrecruitment/` — `StaffRecruitment`, `...Department`, `...Question`, 상태 enum 3종 |
| 영속성      | `infrastructure/persistence/staffrecruitment/` — JPA repository와 포트 구현                    |
| application | `application/staffrecruitment/StaffRecruitmentService` + command·조회 DTO                      |
| web         | `web/staffrecruitment/` — 공개 컨트롤러, 회장단 컨트롤러, 요청·응답 DTO                        |
| 공통 수정   | `ErrorCode` 5개 추가(FOR148~152), `SecurityConfig`에 공개 GET 경로 2개 추가                    |

설계 결정은 계약(`contract.md`)을 따랐고, 추가로 정한 사항은 다음과 같다.

- 접수 가능 여부와 접수 상태는 저장하지 않고 `StaffRecruitment`에서만 계산한다. 관리·공개 API가 같은 규칙을 쓴다.
- 동시 게시는 애플리케이션 검사와 `published_slot` 유니크 제약으로 이중 방어한다.
- 부서·문항은 보낸 목록으로 전체 교체한다. 3단계 지원서가 참조를 갖게 되면 계약 재검토가 필요하다.
- 응답 시각만 `OffsetDateTime`으로 변환한다. 기존 API의 `LocalDateTime` 직렬화는 바꾸지 않았다.
- 공개 응답의 부서에는 frontend 타입에 맞춰 `active` 필드를 포함하되 비활성 부서는 목록에서 제외한다.

## 검증 결과

| 검증                                              | 결과                                                            |
| ------------------------------------------------- | --------------------------------------------------------------- |
| `./gradlew.bat compileJava`                       | 통과                                                             |
| `./gradlew.bat test --tests "*StaffRecruitment*"` | 통과 — 단위 테스트 18개 (도메인 11, 서비스 7)                     |
| 엔티티 ↔ V5 SQL 컬럼 대조 (수동 스크립트)          | 불일치 없음                                                       |
| `./gradlew.bat build`                             | **통과** — 테스트 343개, 실패 0·오류 0·건너뜀 34                  |
| `FlywayMigrationSchemaTest`                       | **통과** — Testcontainers MySQL 8.0.46에 V5 적용 후 엔티티 대조   |

Docker Desktop을 기동해 Testcontainers 기반 테스트를 실행했다. 첫 기동에 `docker-desktop` WSL 배포판 초기화가 필요해 엔진 준비까지 시간이 걸렸고, 권한 서비스(`com.docker.service`)는 관리자 권한이 있어야 시작된다.

### 남은 검증

1. 로컬 MySQL + `local` 프로파일로 서버 기동 — `ddl-auto: validate`로 스키마 일치를 한 번 더 확인하고 실제 요청을 호출한다. 이 PC에는 로컬 MySQL이 없고 설정이 `127.0.0.1:3307`을 바라보므로 Docker로 DB를 띄워야 한다.
2. 회장/부회장 ADMIN 계정으로 생성 → 게시 → 공개 조회 → 마감까지 수동 확인.
3. 일반 ADMIN·비로그인 요청의 403·401 확인.
4. frontend 어드민 화면 → 홈 배너 → `/club/recruit` 반영까지 함께 확인 (한지석과 공동).
